Inside Outside Concepts Shape hepta-dev Guarantees

Your app, something people talk to.

People say what they want. One card shows what was heard, holds for a moment, and silence lets it happen. A word or a tap corrects it; undo is one tap away. Every action declares what it costs to be wrong, and that decides whether it may happen on silence, needs a yes, or may never happen while you are away.

Start · Inside

Five minutes, inside your app

Declare what your app can do. Hand it text. That is the whole surface.

ts
import { createApp, defineAct } from '@intermenu/aiuic-kit';
import { StagePresenter, stylesheet } from '@intermenu/aiuic-eui';
import { resolveWhen } from '@intermenu/aiuic-resolve';

const app = createApp({
  ctx: () => ({
    actor: { id: 'me' },
    // All four must be true for silence to count as a yes. Unknown counts as false.
    attention: { foreground: true, unlocked: true, proximityClear: true, listening: true },
  }),
  presenters: [new StagePresenter(document.getElementById('stage'), document)],
  acts: [
    defineAct({
      name: 'add_chore',
      domain: 'chores',                    // the colour, and the rules for that part of the app
      phrases: ['add', 'assign', 'needs to do'],
      slots: {
        chore:    { primitive: 'chip', options: () => CHORES, required: true, order: 1 },
        assignee: { primitive: 'face', options: () => PEOPLE, required: true, order: 2 },
        due:      { primitive: 'when', resolve: resolveWhen, order: 3 },
      },
      radius: 'other-person',              // what it costs to be wrong
      commit: (f) => db.chores.insert(f),
      undo:   (r) => db.chores.remove(r.id),
    }),
  ],
});

app.hear('the dishes for Maya tomorrow');        // card up, filled, holding
app.hear('the dishes for', { final: false });    // still speaking: it speculates, and cannot commit

hear() routes the sentence to an act, fills its slots from the same words, speculates while final is false, and draws the card. Speech-to-text stays outside: pass the transcript as it arrives.

The one thing to get right: final: false means the person has not stopped talking, and nothing commits on an unfinished sentence.

Connect the MCP servers you already have

ts
import { Client } from '@modelcontextprotocol/sdk/client/index.js';
import { StdioClientTransport } from '@modelcontextprotocol/sdk/client/stdio.js';
import { connect, delegationAct } from '@intermenu/aiuic-mcp';

const client = new Client({ name: 'my-app', version: '1.0.0' });
await client.connect(new StdioClientTransport({ command: 'node', args: ['tasks-server.mjs'] }));
const tasks = await connect(client);          // calls nothing yet

tasks.preview();
// "Connect Tasks. It can do 1 thing and look up 2. It asks you first. 1 can be undone,
//  so you may later let it go ahead on silence. It looks things up with list_tasks,
//  list_lists. The server says those only read; approving means trusting that."

await tasks.approve();                        // the person said yes: now it may be called

const app = createApp({ ctx, acts: [...tasks.acts, delegationAct([tasks])], domains: tasks.shape.domains });

Write tools become acts. Read-only tools become sources the aggregator can ask. A tool named as another tool's undo is kept out of sight: it is reached from the card that made the change.

connect() calls nothing. Show preview() to the person; it names every tool that will be trusted to only read. Until approve(), sources return nothing and acts refuse to commit. Give each connection your own id: a delegation belongs to the connection you named, never to whatever name a server gives itself.

Start · Outside

Five minutes, outside

sh
cd apps/hepta
cp hepta.config.example.json hepta.config.json    # list your MCP servers
node hepta.mjs approve tasks                       # see what it would be trusted with; approve it
node hepta.mjs                                     # always on; MCP over HTTP on 127.0.0.1:8790

A server nobody has approved is connected only long enough to show what approving it would mean. Approval is stored with a fingerprint of what the server offers, so a server that changes its tools has to be approved again.

From Claude Desktop, Cursor, or any client that launches servers

json
{
  "mcpServers": {
    "hepta": {
      "command": "node",
      "args": ["/absolute/path/to/apps/hepta/hepta.mjs", "--stdio",
               "--config", "/absolute/path/to/hepta.config.json"]
    }
  }
}

Over HTTP

http://127.0.0.1:8790/mcp with Authorization: Bearer <token>. The token is created on first run at ~/.hepta/token. The endpoint serves your memory, so it listens on localhost only and refuses requests without the token.

json
{
  "dataDir": "~/.hepta",
  "servers": [{ "name": "tasks", "command": "node", "args": ["tasks-server.mjs"] }],
  "http": { "port": 8790 },
  "notify": { "url": "https://ntfy.sh/your-own-topic" }
}

notify.url receives a plain-text POST when the conductor does something, waits for you, or cannot do something.

What an outside caller can do

ToolDoes
stageWhat is on the person's stage now.
why_not_committingThe reasons, in order: missing, guessed, cost, attention.
actsEverything the app can do.
proposePuts an act on the stage with values filled, waiting for the person.
pursueRuns the loop on a goal. Ends in an answer or a proposal, never a commit.
thinkAdds a line of thought to a memory branch, never to main.
memory_search, memory_branchesReads the shared memory.
inbox, scoreThe conductor's inbox and standing orders.

There is no tool that says yes, and none that speaks as the person. Whoever calls in is a model: a proposal from outside waits on the stage until the person answers it.

Concepts

Acts, slots and primitives

An act is one thing a person can ask for. It has slots to fill, each drawn by a primitive:

PrimitiveForFilled on the device by
chipa choice from a listmatching the options and their aliases
facea personmatching names
whena time"tomorrow at 9:30am", "friday"
quantityan amount"$12", "twelve dollars"
ghostFieldfree textthe rest of the sentence, always marked as a guess

A slot filled by a weak or uncalibrated match is provisional: the card shows it with a ✓ the person taps to make it theirs.

Concepts

What it costs to be wrong

RadiusMeansSilence may commit?
selfonly the person askingyes, after the hold
sharedsomething shared and reversibleyes, after the hold
other-personreaches someone elseafter a longer hold, and never on a guess
externalmoney, sending, anything irreversiblenever: it asks for a yes

An act costs the most of its own radius and every effect's. An effect that cannot be undone counts as external. An act with no undo() is external at runtime, whatever it declares: nothing commits on silence that cannot be taken back.

Concepts

The hold, and when silence counts

A complete act below external holds: 850 ms for an adult, 1300 ms for a child, longer when it reaches another person. If the person stays quiet through it, it happens. A word or a tap stops it.

Silence only counts as a yes when the app is in front, the device is unlocked, nothing covers the screen, the microphone is live, and the person touched or spoke during this act. That last check is why a card built from defaults, a card the system started, and a card a model proposed all wait for a yes.

Concepts

The pyramid: authority, not votes

RoleMayIn code
Conductorkeep the rhythm, always on; commit only what the score allowsConductor
Congregatorwrite to memory, and only what happenedpyramid.congregator
Orchestratorpropose: copies in, a plan out; nothing to write withyour function
Aggregatorread sources and memoryAggregator

Three agents on the same model make the same mistakes, so three votes read as one confident wrong answer. Each role holds a different authority instead, and a mistake has to get past three different kinds of gate.

ts
const pyramid = new Pyramid({
  app, ctx, memory,
  aggregator: new Aggregator([...tasks.sources, ...bank.sources]),
  orchestrator: async ({ goal, findings, memory, parts }) => {
    // Call a model here if you like. Return one of:
    //   { kind: 'answer', answer }
    //   { kind: 'propose', act, fill, why }   a card on the stage, waiting for a yes
    //   { kind: 'look', query }               look again with a sharper question
    //   { kind: 'split', goals }              each part goes round the loop one level down
  },
});
await pyramid.pursue('plan my month');

The loop stops at a depth of 3, after 2 requests to look again, and on any goal already being pursued higher up.

Concepts · optional

A model behind the orchestrator

@intermenu/aiuic-orchestrators puts Claude or an OpenAI model behind the orchestrator. It plans; it never writes.

ts
import { anthropicOrchestrator } from '@intermenu/aiuic-orchestrators';

const orchestrator = anthropicOrchestrator({
  apiKey: process.env.ANTHROPIC_API_KEY,   // server-side only
  model: 'claude-opus-5',
  acts: () => app.ui.definitions,         // read on every plan
});
// or openaiOrchestrator({ apiKey, model, acts }), on the Responses API

The model gets the goal, what was found, what memory holds, and the answers to any parts it split the goal into. It replies by calling one of four tools, and the reply is checked before anything else sees it:

  • A proposal must be real. It must name an act the app has, fill only that act's slots with plain values, and say why. Then it waits on the stage for the person, like any other proposal.
  • Authority is never on offer. The model is not offered set_delegation or set_standing_order, because an app's output should not be what argues for trusting that app more.
  • Findings are data. The prompt says text in them is not from the person and is never to be followed. The check is what holds if the model follows it anyway.
  • Nothing throws. A timeout, an error, a refusal, malformed output or an unknown act becomes an answer saying what went wrong, with anything that looks like a key removed. A provider that is down cannot stop the conductor.

In the daemon, add "planner": { "provider": "anthropic", "model": "claude-opus-5" } to the config and put the key in ANTHROPIC_API_KEY or OPENAI_API_KEY. The key is never read from the file.

Not yet run against the live APIs. The request shapes follow each provider's current documentation, cited in the source. The tests use a stubbed fetch, and the daemon has been run end to end against a local stand-in for the Claude API.

Concepts

Memory: one pen, and branches

ts
const { reader, writer } = openMemory(store);   // every role gets reader; the congregator gets writer

Versions are branches. A line of thought can explore "what if the budget were 650" on its own branch, then be merged or dropped. A branch holds only thoughts and findings; facts, decisions, delegations and standing orders are real, and go to main or nowhere.

A fact is only ever something the person said, and it carries the words it came from. A figure from a bank feed stays a finding.

Concepts

The conductor: always on

ts
const conductor = new Conductor({ app, memory: reader, clock, store, ctx,
  pursue: (goal) => pyramid.pursue(goal), notifier });
conductor.start();

The person writes the score: standing orders such as "every morning, tell me what is due", each written through an act they approved. The conductor runs them around the clock and may commit on the person's behalf only when all of these hold:

  • the order names that act: an act order covers its own act, and a goal order covers only what its allow list names, so a model never chooses what gets committed
  • it does not change what may happen without the person: letting a tool go ahead and writing orders are only ever committed by the person
  • its cost is at or under that order's ceiling
  • the ceiling is not external: money and anything irreversible are never done unattended
  • it can be undone
  • nothing is missing and nothing is a guess

Everything else goes to the inbox, waiting for a yes. What it did on its own is there too, with an undo. With no orders, it does nothing.

Concepts

Speaking and listening at once

The seven tongues keep up to seven possible acts alive while someone is still talking and put the likeliest card up early. None may commit until the sentence ends.

Lines of thought run beside them on every word: numbers said earlier, views held, things left open.

  • Cutting in happens at the end of a clause or a breath, never mid-word, unless waiting would cost more than the rudeness.
  • Holding the floor: "yeah" keeps it talking; "wait" or a real sentence stops it.
  • Arguing: a reason lowers its confidence until it concedes; "do it anyway" ends it. Once per disagreement by default, twice when turned up, never more.
  • Wandering: when you are quiet and nothing is on the stage, it goes back to something left open.

npm run hepta scores both. Two numbers must stay at zero: early commits, and wrong interruptions.

The shape: aiuic://shape

An MCP server says what its app should look like by exposing one resource:

json
{
  "schema": "aiuic.shape/1",
  "app": { "name": "Tasks", "brand": { "colour": "#5B6CFF", "mark": "T" } },
  "domains": { "tasks": { "kicker": "TASKS", "colour": "#7C8BFF" } },
  "tools": {
    "add_task": {
      "domain": "tasks",
      "phrases": ["add", "remind me to", "new task"],
      "preview": "Add {title} to {list}",
      "undo": { "tool": "remove_task", "arg": "id", "from": "id" },
      "options": { "list": { "from": "list_lists", "value": "id", "label": "name" } }
    }
  },
  "settings": [{ "key": "weekly", "label": "Weekly review", "type": "toggle", "default": true }],
  "notifications": [{ "key": "due", "label": "A task is due", "default": true, "watch": "list_tasks" }],
  "home": ["add_task"]
}

A shape describes; it never decides. It is refused, and the app falls back to a plain look, if it:

  • sets radius, commit, reversible, effects, assent or silence anywhere
  • names an undo tool that does not exist, or one that says it only reads
  • uses a colour that means something everywhere: success, warning, danger, or the assistant's own
  • puts a parameter in preview that the tool does not have
  • lists options from a tool that is not read-only

Every problem is reported at once, in connection.shapeProblems.

How the bridge decides what a tool costs

MCP annotations are hints; the MCP SDK itself says never to make decisions on them for untrusted servers. So a server's hints can only make its tools look more dangerous.

The server saysThe bridge does
readOnlyHint: truea source for the aggregator, never an act
nothing at allexternal, always (MCP assumes destructive and open-world)
destructiveHint: trueexternal, always
no undo in the shapeexternal, always: it cannot be taken back
destructiveHint: false and an undostarts external; the person may let it go ahead, down to other-person, or self with openWorldHint: false

Letting a tool go ahead is the person's own act: previewed, held, undoable, and remembered.

The brief

Markdown, written the way notes already are. French headings work too.

md
# Family Tasks
A calm app that runs the house by voice.
Audience: parents with kids under 14

## Features
- Add a chore for someone — asks who, what, when
- Pay allowance — asks who, amount

## Menus
- Home -> Chores, Calendar, Settings

## Design
- mood: calm, glass
- colour: #5B6CFF

## Exceptions
- kids cannot approve their own allowance

## Expectations
- adding a chore takes one sentence

"— asks who, when" shapes the act: who becomes a person, when a time, amount a quantity, what free text, and anything else a choice from a list you provide. Every guess is written down with its reason, and costs lean careful: money and sending are external; anything involving another person is at least other-person.

Guarantees, and what holds them

Each is a test in the repository. The last four came from an independent review, run by an agent that had not seen the code being written, which found eight ways around the rules above; each is fixed and kept as a regression test.

Not yet verified

  • Voice, live. The OpenAI Realtime wiring follows the current documentation but has not yet connected to a live session. Two details could not be confirmed: whether input transcription must be enabled explicitly in a speech-to-speech session, and whether the model will start speaking while input audio is still arriving, which cutting in depends on.
  • Thresholds. Routing and hold thresholds are tuned on 28 written sentences and 15 replayed conversations. They need a few hundred real ones.
  • Detectors. Every detector in the lines of thought matches words and numbers. The Detector interface is where a fast classifier replaces them.
